# AI-First Company

AI-First Company is a vendor-neutral organizational model for organizations in which Human and AI Performers operate within one coherent organizational system.

## Start here

### Complete model. Start small. Grow with confidence.

Start with one real organizational need. You do not need to understand or implement the complete framework first. The LLM guided path helps you identify what matters now, what can wait, and what remains open. The complete model stays available as your organization evolves.

This progressive approach keeps Scope, gaps, and assumptions explicit. It supports deliberate implementation without presenting partial coverage as complete conformance.

> **Information safety:** Content, uploaded files, connected tools, logs, and provider retention may expose information outside your organization. Never share passwords, private keys, tokens, API keys, recovery codes, or other secrets. Share only what is necessary and prefer redacted, pseudonymized, aggregated, synthetic, or representative information. Read the [full information safety guidance](00-introduction/USING_AI_FIRST_COMPANY_WITH_AN_LLM.md#information-safety) before using confidential or personal information.

1. **Copy the Short Start Prompt below.** Use it to ask about the framework or begin with one real organizational need. Add your question or need after `My first request:`, or leave it empty and the LLM will help you start. [Other prompt options](00-introduction/USING_AI_FIRST_COMPANY_WITH_AN_LLM.md#how-the-prompts-relate) are available when you need them.

   ```text
   Help me understand or apply AI-First Company:
   https://github.com/YamartiHQ/ai-first-company

   Read `PROJECT.md` first and follow its document authority. Confirm repository access and identify the release, tag, or commit used; a URL alone is not proof of access. If authoritative content is unavailable, request only the exact files or sections needed and do not guess.

   If my request is about the framework itself, answer it directly at the requested depth with repository citations. Explain defined terminology in plain language, label examples as examples, and do not force an application workflow.

   If my request concerns an organizational need, begin with that bounded need without requiring a complete organizational intake or day-one implementation of the complete model. Ask only what materially changes the next step and make safe provisional progress with labelled assumptions.

   When material, distinguish: applicable now and covered; applicable now but uncovered; deliberately deferred; not currently applicable with a stated basis; uncertain or requiring Evidence; and contradicted by the proposed realization. State the consequence of relevant gaps and any temporary restriction or narrower Scope. Do not present partial coverage as complete conformance.

   Be critical rather than confirmatory. Separate framework consistency, technical feasibility, economic viability, proportionality, organizational fitness, Evidence, assumptions, recommendations, and accepted Decisions. Preserve Authority and information boundaries. Tell me which material results should be retained outside the conversation, where, and what approval or adoption remains necessary.

   If my first request is empty, ask one simple question: whether I want to understand part of the framework or apply it to one real organizational need.

   My first request:
   ```

2. **Understand the Core Idea.** Read [The Core Idea](00-introduction/THE-CORE-IDEA.md).

3. **Study the complete model.** Continue with [Architecture](01-architecture/ARCHITECTURE.md), then [Reference Design](02-reference-design/REFERENCE_DESIGN.md), and then [Technical Requirements](03-technical-requirements/TECHNICAL_REQUIREMENTS.md).

## Status and use

AI-First Company v2.0 is an openly licensed conceptual and normative model. It has been checked for conceptual coherence and internal consistency, but it has not yet been validated through real organizational operation.

You may use, adapt, and build on the model under the CC BY 4.0 license. Please retain attribution, link to the original repository, and describe material changes.

## Next step: reference implementation and evaluation

The next phase will test the framework through a bounded end to end implementation. The resulting Evidence may support, limit, contradict, or refine its assumptions.

Until practical Evidence exists, v2.0 should not be presented as proven or generally effective. It does not yet establish practical effectiveness, proportionality, technical feasibility, economic viability, or organizational fitness. One implementation alone cannot establish general validity.

Read the [planned evaluation and its limits](PROJECT.md#planned-reference-implementation-and-empirical-evaluation).

## Use AI-First Company with an LLM

[Using AI-First Company with an LLM](00-introduction/USING_AI_FIRST_COMPANY_WITH_AN_LLM.md) provides the Short Start Prompt, transparent complete prompt, later-session Resume Prompt, repository-grounding checks, and practical paths for new organizational realizations and existing-organization transformation.

The repository documents remain the stable knowledge and requirements basis. The LLM is a replaceable interpretation, interaction, and current-research layer. It may help a practitioner apply the model, request missing organizational Context, evaluate a proposed design, or research current technology choices against the Technical Requirements without becoming authoritative.

The directly copyable prompt near the top of this README is the lowest-friction entry. The usage document provides fuller instructions when the work becomes material or persistent.
